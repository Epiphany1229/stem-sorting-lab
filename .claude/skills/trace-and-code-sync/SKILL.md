# 轨迹与代码同步（项目专属规范）

> 来源：本项目 `docs/trace-protocol.md` v1 + 需求文件第六节。**本地项目 Skill，不是外部下载内容。**

## 何时必须使用

- 新增/修改任何排序算法（阶段 2、阶段 5）
- 修改播放器、代码高亮、事件解释、指标计数
- 修改轨迹响应字段或前端类型
- 审查"动画是否真的来自 Python 执行"

## 不可违背的红线

1. **只有 Python 真实执行才产生事件**。前端只消费 `states[]` 与 `events[]`；不得推导事件、不得按时间轴轮流点亮代码、不得在前端重写比较/交换规则。
2. **唯一可信代码源**：学生看到的源码来自 `inspect.getsourcelines` 取的实际执行模块；插桩调用写在函数体内，展示时标记 `kind: "trace"` 并允许折叠，**行号绝不重排**。
3. **禁止 `sorted()` 造假**：测试可以用 `sorted()` 做参照，实现里不得先排好再回放。
4. **稳定唯一 ID**：元素 ID 与数值解耦（`it-0`…），重复数值也要能追到原始位置；排序前后不得丢元素。
5. **状态语义显式**：每个事件给 `state_before_id` / `state_after_id`；交换事件前后状态必须可还原；`states[0]` 是输入。
6. **指标分账**：`comparisons` / `swaps` / `writes` 分开累计；一次交换 = `swaps+1`、`writes+2`；单点写入只记 `writes`。
7. **可重复**：同输入同参数 ⇒ 逐字段相同；不得注入时间戳、随机数或依赖 dict/set 迭代顺序。
8. **上限保护**：输入长度、事件总数都设上限；超限返回 422，**不得**静默截断。
9. **回退不逆算**：`prev` 只回退到已有快照。

## 代码行映射规则（改算法时必须同步维护）

| 插桩 | 放置位置 | 高亮目标 |
|---|---|---|
| `emit_compare(...)` | 比较语句**之前** | **下一条**同块语句（`if` 行） |
| `emit_swap(...)` | 交换赋值**之后** | **上一条**同块语句（赋值行） |
| `emit_mark_sorted(...)` | 每轮循环体**第一句** | 所在 `for` 行 |
| `emit_done(...)` | `return` **之前** | **下一条**语句（`return` 行） |

规则由 AST 在**导入期**建立，解析失败立刻抛错（不允许运行期才发现漂移）。
测试必须：① 每个 `code_line_ids` 都能在 `code.lines` 命中；② 目标行 AST 节点类型符合预期；③ 每种 `event_type` 至少覆盖一次。

## 修改轨迹协议的流程

1. 先改 `docs/trace-protocol.md`（升 `protocol_version` 或加可选字段）。
2. 改后端 Pydantic 模型与模板解释。
3. 改前端 `types.ts` + 运行时校验（`traceValidation.ts`）。
4. 跑后端 `uv run pytest`、前端 `pnpm test:run` 与 `pnpm exec tsc --noEmit`。
5. 用真实后端响应验证一次（不可只用前端手工 fixture）。

## 解释文案

- 由**后端固定模板 + 真实事件参数**生成（繁体中文 + 英文两字段），不调大模型、不联网。
- 日期/温度等必须来自真实记录；不得写死。
- 键名稳定（便于测试），缺任一语言即失败。

## 反例（出现即打回）

- 前端有 `if (a > b)` 之类比较逻辑来决定动画。
- 播放器自己算下一个数组状态。
- 代码面板显示另一份手写"教学代码"。
- `writes` 被当作 `swaps` 统计。
- 轨迹里出现 `time.time()` 或 `random`。
