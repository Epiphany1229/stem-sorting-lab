# 香港天文台安全取数（项目专属规范）

> 来源：需求文件第七、八、九节 + `docs/data-sources.md` 实测结论。**本地项目 Skill。**

## 何时必须使用

- 写/改 `backend/app/data_sources/hko/`
- 加缓存、调度、限速、重试、熔断
- 处理缺失值、质量标记、单位、精度
- 实现"最近 30 天"窗口或 CSV 导入

## 网络前提（本机实测，务必遵守）

1. **必须 `httpx.Client(trust_env=False)`**。本机注册表里有个失效代理 `127.0.0.1:10809`，默认 `trust_env=True` 会报 `ConnectError: EOF occurred in violation of protocol`；设 `False` 后实测 HKO 返回 200。
2. **不要用 curl / Invoke-WebRequest 做连通性判断**：本机 Windows Schannel 凭据故障，对所有站点都报 `SEC_E_NO_CREDENTIALS`，会误判为"断网"。
3. **只有后端访问官方源**；前端只能打本项目 API。不提供任意 URL 抓取接口。

## 合规访问（自我约束，不是官方保证）

| 项 | 取值 |
|---|---|
| 同主机并发 | 1 |
| 请求间隔 | ≥ 3 秒 + 少量 jitter |
| 重试 | 有限指数退避，最多额外 3 次 |
| 429 | 必须遵守 `Retry-After`，并暂停该主机新请求 |
| 403 | 不得重试 |
| 熔断 | 连续失败达阈值后停止自动抓取，提示管理员 |
| 每日预算 | 可配置上限；"更新"按钮不得绕过缓存/冷却/预算 |
| 全局唯一抓取者 | 用数据库锁/租约保证，多进程也不能各自狂抓 |
| 停止开关 | 环境变量一键关闭外部抓取 |
| 条件式请求 | 服务器支持时用 `ETag` / `Last-Modified`；**本机尚未观测到 API 响应头，启用前必须实测** |

不换 IP、不用代理池、不伪造身份、不压力测试。`robots.txt` ≠ 授权。

## 数据语义（违反即造假）

1. **逐日最高/最低温只有月表**（`opendata.php`，Monthly）：**当月返回 `data: []`**（HTTP 仍是 200，不是 404）。后端必须判断 `data` 为空，不能只看状态码。
2. **产品已定窗口**：以**最后可用日**为锚点回推"最近有数据的 30 天"；界面必须显示真实起止日期，并注明"当月官方数据尚未发布"。**禁止**静默替换为最近有数据的区间而不提示。
3. **不得用实时数据倒推历史**：`rhrread` 只有单次观测，无日汇总。
4. **缺失不填 0**：`***`（无数据）/ `#`（不完整）/ `C`（完整）三态必须入库并在 UI 区分。
5. **保留原始精度**：值是一位的字符串（如 `"34.4"`），不得 `int()` 取整。
6. **降雨「微量」**：官方定义 `Trace = rainfall less than 0.05 mm`，需独立标记，不得记为 0。
7. **风向不得算术平均**；湿度只有天文台总部 1 站，不能冒充全港；降雨是 18 个**行政区**而非测站。
8. **测站字典以 `docs/data-sources.md` §5.4 为准**（39 站，来自官方 PDF）。**行政区映射官方未提供**，不得按站名猜。
9. **API 显示名 ≠ 正式名**：`HKO` 在 API 里显示为「天文台」，正式名是「香港天文台」。
10. 旧缓存可展示，但必须显示观测日期、抓取时间、"数据可能未更新"。

## 失败与演示模式

- 网络/解析/校验/算法错误要分门别类记录日志。
- 失败时给用户可理解的错误说明，不得静默回退到虚构数据。
- 演示数据必须放在独立模式并常驻醒目标识；用户可导入官方 CSV 时应校验格式。

## 测试方式

- 常规测试**不依赖实时网络**：用固定样本 + 模拟 HTTP 响应覆盖 429/Retry-After/403/超时/缓存命中/熔断。
- 官方连通性测试单独做成可选标记（如 `@pytest.mark.live`），默认不跑。
- **禁止**对官方服务做压力测试或并发测试。
