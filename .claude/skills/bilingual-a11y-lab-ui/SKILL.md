# 双语与无障碍实验台 UI（项目专属规范）

> 来源：需求文件第 17–19、42–82、839–862、923–929 行 + 阶段 1 已落地实现。**本地项目 Skill。**

## 何时必须使用

- 新增任何学生可见文案（按钮、标题、图例、提示、错误、加载态、悬停文本）
- 新增/修改颜色、状态标记、动画
- 做响应式布局或验收测试
- 新增图表（Plotly）或代码面板

## 双语形态（不是语言切换，不是左右并排）

- **繁体中文在上、对应英文紧贴在下**，纵向堆叠。
- 繁中：正文约 **16–18px**（实现值 17px）；英文约 **13–15px**（实现值 14px）；中英间距 **2–4px**（实现值 3px）。
- 分别设置 `lang="zh-Hant"` 与 `lang="en"`。
- 按钮/链接仍是**一个**交互元素，内部包一层 `BilingualText`，不得做两个按钮。
- Python 关键字、变量名、API 标识符**不翻译**。
- 英文完整显示，不得用省略号隐藏关键教学内容。
- 文案只能来自 `src/i18n/dictionary.ts` 的成对键；组件内禁止硬编码中文。
- **学生可见文案禁止简体中文**；源码内部注释用简体（这是明确分工）。
- 自检：字典键 zh-Hant/en 同时非空 + 简体专有字黑名单扫描（注意排除「站/按/覆」等繁简同形字避免误报）。

## 无障碍硬要求

- 键盘可完成全部操作：播放/暂停（空格）、步进（← →）、弹窗（Esc、Tab 焦点圈定、初始焦点、关闭后焦点归还）。
- 控件有可访问名称（`aria-label` 或可见标签）。
- 状态不能只靠颜色：**颜色 + 图标 + 文字**三通道（待处理 / 正在比较 / 正在交换 / 已排好序）。
- 屏幕阅读器不得逐帧播报：`aria-live="polite"` 只用于**手动步进**的简短摘要；连续播放不播报。
- 尊重 `prefers-reduced-motion`：去掉过渡动画，但状态推进逻辑不变。
- 弹窗用 `role="dialog"` + `aria-modal="true"` + `aria-labelledby`；反馈用 `role="status"`。
- 代码高亮**不得**自动滚动整个页面：只滚动代码容器内部。
- 小屏（<768px）：动画 → 代码 → 控制栏 上下排列，关键信息不需要横向滚动。
- 对比度：正文与背景 ≥ 4.5:1；英文次级文字也要保持足够对比（实现约 8.4:1）。

## 设计语气

「精致、有趣、可信赖的互动科学实验室」，不是密集的企业仪表盘，也不是卡通儿童页。
避免廉价 AI 模板感：不要渐变滥用、不要无意义的玻璃拟态、不要一排制式卡片当首页。

## 验收清单

1. 每个新 key 都有中英两份，且繁中无简体残留。
2. 视觉验收至少覆盖桌面/平板/手机三档（条件允许时用 Playwright 截图）。
3. 键盘全流程可完成，焦点可见。
4. 减少动画偏好下功能完整。
5. 文字不溢出、控制栏不拥挤、图表标签不重叠。
